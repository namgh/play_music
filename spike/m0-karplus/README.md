# M0 — Karplus-Strong 프로토타입

`sound.md` 10절의 M0. **버릴 코드다.** M1에서 Rust→WASM으로 다시 쓴다.

## 무엇을 검증하는가

딱 하나: **줄 길이를 바꾸면 소리가 달라지는가.**
물리 모델링은 문서로 판단이 안 된다. 여기서 "차이가 안 들린다"가 나오면 제품 컨셉(`plan.md` 5-3)을 재검토해야 한다.

같이 확인할 것:
- 정수 딜레이로 반올림하면 음정이 실제로 얼마나 틀어지는가 (`sound.md` 6-2)
- 강성을 올리면 상위 하모닉이 위로 밀리는가 (인하모니시티)
- 뜯는 위치가 하모닉 노치를 만드는가

## 실행

```bash
npm run m0     # http://localhost:5173
npm test       # 음정 정확도 회귀 테스트
```

`npm run dev` 는 비워 뒀다 — 앱을 스캐폴드하면 그게 Vite 개발 서버가 된다.
스파이크는 그때도 `npm run m0` 로 남는다.

**Chrome 에서 열 것.** 워크렛 안에서 ES 모듈 `import` 를 쓰기 때문에 브라우저에 따라 실패할 수 있다.
`file://` 로는 안 된다 — `audioWorklet.addModule()` 이 http 를 요구한다.

## 파일

| 파일 | 역할 |
|---|---|
| `ks-string.js` | DSP 전부. 브라우저와 노드 테스트가 **같은 이 파일**을 쓴다 |
| `ks-processor.js` | AudioWorklet 껍데기 — 보이스 풀 12개, 메시지 처리만 |
| `index.html` | 조작 화면 (A/B 슬롯, 슬라이더, 건반, 스펙트럼) |
| `test-pitch.mjs` | 음정 정확도 자동 테스트 (`sound.md` 11-1) |
| `serve.mjs` | 의존성 없는 정적 서버 |

DSP를 워크렛에서 분리해 둔 이유: 브라우저에서 **들은 소리**와 테스트가 **측정한 음정**이
같은 코드에서 나와야 검증에 의미가 있다.

## 들어볼 순서

1. `오디오 시작` → 건반이나 `E 코드`
2. **줄 길이 슬라이더를 300 ↔ 900 으로 크게 흔든다** — 여기서 차이가 안 들리면 그게 결론이다
3. 스케일 프리셋 `레스폴 628` ↔ `스트랫 648` — 제품이 실제로 주장할 수준의 미세한 차이.
   A/B 슬롯에 각각 넣고 Tab 으로 전환하며 비교한다
4. `분수 딜레이 OFF` → 고음(위 옥타브 오른쪽)을 쳐 본다. 음이 틀어지는 게 들려야 한다

## 미해결 — 서스테인 파라미터가 고음에서 거짓말을 한다

`sustainSec = 3.0` 을 지정했을 때 실제 T60 (스트랫 648mm):

| | E2 82Hz | E3 165Hz | E4 330Hz | E5 659Hz | E6 1319Hz | C8 4186Hz |
|---|---|---|---|---|---|---|
| damping 0.05 | 93% | 91% | 88% | 78% | 56% | **6%** (182ms) |
| damping 0.18 | 90% | 84% | 85% | 75% | 35% | **2%** (51ms) |

원제로 루프 필터의 감쇠는 주파수에 비례해 커지므로, 고음에서는 **기본음 자체가 루프 필터에
먹혀** `sustainSec` 이 감쇠를 제어하지 못한다. 기본값을 0.18 → 0.05 로 낮춘 것은 완화이지 해결이 아니다.

실용 음역(E2~E5)은 78% 이상이라 M0 판정에는 지장이 없고, 고음이 빨리 죽는 것 자체는 실제 줄과
같은 방향이다. 문제는 **파라미터가 말한 값과 다르다**는 것, 그리고 밝기와 서스테인을 따로
조절할 수단이 없다는 것.

**해결 방향 (M1 이후)**: 루프 필터를 기본음에서 단위 이득으로 정규화하고 T60은 루프 게인만으로
정하면 `sustainSec` 이 정확해진다. 단 그렇게 하면 DC 이득이 1을 넘어 발산하므로 **루프 안
DC 차단기가 전제**다. DC 차단기도 위상 지연을 만들므로 아래 2번 보정에 함께 들어가야 한다.
Rust 코어에서 처리할 일이지 이 스파이크에서 할 일이 아니다.

## 여기서 배운 것 (M1로 넘길 것)

1. **올패스 보간 계수를 교과서 공식 `c=(1-d)/(1+d)` 로 쓰면 고음에서 틀어진다.**
   그 공식은 DC에서만 맞는다. 기본음 주파수에서 계수를 직접 풀어야 한다 (C8에서 10~19센트 차이).
2. **루프 안의 모든 필터 위상 지연을 빼야 한다.** 감쇠 필터와 분산 올패스가 각각 지연을 만든다.
   분산 3단은 1음 주기가 11샘플인 C8에서 4샘플을 먹는다 — 무시할 수 없다.
3. **감쇠 파라미터는 고음의 기본음까지 죽인다.** 원제로 루프 필터의 감쇠는 주파수에 비례하므로
   `damping=0.18` 에서 C8이 50ms 만에 소멸했다. 0.05 부근이 실용 범위.
4. **음정 측정 창은 신호 엔벌로프에 맞춰야 한다.** 고정 구간을 쓰면 이미 소멸한 고음의
   노이즈 위상을 재게 되고, 측정값이 통째로 거짓이 된다 (C8을 -53센트로 잘못 보고했다).
5. **여진의 DC를 반드시 빼야 하고, 여진 길이는 딜레이 라인 길이와 정확히 같아야 한다.**
   루프 필터는 DC에서 이득이 정확히 1이라 한 번 들어간 DC는 루프 게인만으로(= T60 전체에 걸쳐)
   빠진다. 음으로는 안 들리면서 헤드룸을 절반 이상 먹고 노트를 쌓으면 누적된다.
   C8에서 전체 RMS의 60%가 DC였고, 그 때문에 감쇠 측정이 3초로 나와 3번 문제를 가리고 있었다.
   여진 길이를 `delayInt + 1` 로 잡으면 첫 샘플이 한 번도 읽히지 않아(첫 읽기 인덱스가 1)
   평균을 0으로 맞춰도 순환 내용의 합이 0이 아니게 된다 — **off-by-one 하나가 DC 모드를 살린다.**
   → M2의 앰프 비선형은 DC를 새로 만들어내므로, 그때는 여진 처리로 안 되고 **루프 안 DC 차단기**가 필요하다.

## 의도적으로 안 한 것

- **룩어헤드 스케줄러** — 스트럼은 `setTimeout`. 직접 구현은 M1 이후 (`plan.md` 5-2)
- **소프트 리미터(tanh 등)** — 비선형 단계는 오버샘플링이 전제다 (`sound.md` 6-1).
  오버샘플링 없이 비선형을 넣으면 우리가 금지한 에일리어싱을 우리 데모가 만든다. 게인으로 피했다
- **바디/캐비닛 IR, 픽업, 앰프** — M2
- **파라미터 스무딩** (`sound.md` 6-4) — 노트 시작 시점에만 계수를 정하므로 M0에서는 클릭이 안 난다
